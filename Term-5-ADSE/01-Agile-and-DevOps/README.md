# Agile and DevOps

![Agile](https://img.shields.io/badge/Agile-Scrum%20%7C%20XP%20%7C%20Kanban-0A66C2) ![DevOps](https://img.shields.io/badge/DevOps-CI%2FCD-FF6F00) ![GitHub Actions](https://img.shields.io/badge/GitHub%20Actions-2088FF?logo=githubactions&logoColor=white) ![Jenkins](https://img.shields.io/badge/Jenkins-D24939?logo=jenkins&logoColor=white) ![Docker](https://img.shields.io/badge/Docker-2496ED?logo=docker&logoColor=white) ![Jira](https://img.shields.io/badge/Jira-0052CC?logo=jira&logoColor=white)

> Term 5 (ADSE – Advanced Diploma in Software Engineering) · 12 sessions × 2 hours

This module explains **how professional software is planned, built and delivered**. You start with what software is and the classic
Software Development Life Cycle, walk through traditional and iterative process models, then dive into Agile (Scrum, XP, DSDM, FDD, Lean)
and finish with DevOps practices — continuous integration, delivery, deployment and monitoring.
It is a theory-focused module, so each session gives you **step-by-step practicals, templates and checklists**, with small code samples only where they help (tests, pipelines, Dockerfiles).

## 🎯 What You Will Learn

- Explain software characteristics and the phases of the SDLC
- Compare Waterfall, V-Model, Prototype, Incremental, Spiral, RAD and other models and choose the right one
- Apply the Agile Manifesto, write user stories and run Scrum events
- Use XP practices such as TDD and pair programming
- Prioritise with MoSCoW and spot waste with Lean thinking
- Build a CI pipeline with GitHub Actions and describe a complete DevOps pipeline (Jenkins, Docker, Puppet)

## 📋 Prerequisites

- Basic computer and internet skills
- Some programming experience (any language) — helpful for the TDD and CI sessions
- A free GitHub account

## 🚀 Module Mini-Project

**Team Agile Simulation — "CampusConnect" notice-board app** (groups of 4–5)

1. Write a one-page vision and a lightweight SRS (Sessions 1–2).
2. Justify your process model choice with the selector sheets (Sessions 3–5, 10).
3. Create a GitHub Project board with ≥ 15 user stories, MoSCoW tags and story points (Sessions 6–7, 9).
4. Run **two one-week sprints**: planning notes, daily stand-up log, review demo and retrospective notes.
5. Use TDD for at least one module and add a GitHub Actions CI workflow (Sessions 8, 11).
6. Add a Dockerfile and a short release & monitoring plan (Session 12).

**Deliverables:** repo link, board screenshots, sprint documents and a 5-minute presentation of what you learned.

## 🧭 How to Study This Module

1. Read the session README from top to bottom before class (20–30 minutes).
2. Type the code examples yourself instead of copy-pasting — your fingers learn too.
3. Finish the Lab Practice tasks, then attempt the Assignment without looking at the notes.
4. Use the Quick Quiz to check yourself; revisit any section where you missed an answer.
5. Practise the Interview Questions out loud — explaining a concept is the best test of understanding.
